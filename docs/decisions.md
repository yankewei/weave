# Weave：决策汇总与当前方案

本文汇总项目讨论结果。已确认的决定、骨架已采用的组件与当前推荐方案分别记录，不能把候选组件当作已经选定的依赖。当前已实现登录、项目与文档手工变更、任务看板、任务评论与一级回复，以及通过对话生成并确认任务提案。工作空间支持邀请已注册成员、查看成员和移除；移除时解除任务负责人并拒绝其待确认提案，且至少保留一名管理员。文档正文支持上传图片：默认存到部署自带的 S3 兼容存储，管理员可以为工作空间改用自己的 S3 兼容存储，访问密钥使用 AES-256-GCM 加密；图片经服务端代理读取，只有成员可见。对话由 agent 的持久任务执行，文档提案尚未实现。详见[文档闭环实现](document-lifecycle.md)。

## 1. 产品方向（已确认）

- 做一个由 AI 驱动的简洁版 Jira + Confluence，管理项目、文档与任务。
- 对话是主要操作入口：通过对话澄清需求、生成内容、拆分任务及提出修改。
- 保留内容阅读、列表、看板与直接编辑的界面方向，不要求所有操作都通过聊天完成。
- 区分讨论与正式结果，未确认的 AI 内容不能直接成为正式需求。
- 当前项目及仓库使用 Weave 名称；未核查商标、域名，也未确定中文品牌名称。

## 2. 技术与架构（已确认）

| 部分     | 决定                                                       |
| -------- | ---------------------------------------------------------- |
| 语言     | 前端与 agent 使用 TypeScript（ESM）；业务 API 使用 PHP 8.5 |
| 后端     | AMPHP HTTP Server + Router，唯一业务与数据入口             |
| 前端     | React 19 + Vite + React Router，纯客户端 SPA               |
| AI 服务  | Node 24 + Pi Durable + Command Code，只在内网供 api 调用   |
| 数据库   | PostgreSQL 17；agent 用私有 SQLite 保存对话与执行检查点    |
| 应用架构 | nginx + AMPHP API + Pi Durable agent 三个运行单元          |
| 运行方式 | docker compose 启动；nginx 托管 SPA 并分发 `/api`          |
| AI 写入  | 生成提案 → 用户确认 → 校验权限与版本 → 事务写入            |

```text
nginx（唯一入口）
    ├─ SPA 静态文件（web/dist）
    └─ /api/* ─── AMPHP PHP API ─┬─ PostgreSQL
                                 └─ /internal/* ─── agent（Pi Durable）
                                                      └─ SQLite
```

身份、权限、事务、版本与审计都由 PHP 决定；agent 只负责模型执行、持久化和流式快照。浏览器无法访问 `/internal/`。

AI 不直接执行任意 SQL，不自行批准修改。手工编辑与 AI 修改使用相同的业务校验和正式写入规则。

## 3. 每次变更可追踪（已确认）

这是业务功能，不只是后台日志。

- 文档与任务的每次正式变更都保留历史，包括内容、任务状态、负责人、优先级及关联关系的变化。
- 手工编辑、AI 提案应用与历史恢复都必须追踪。
- 记录变更时间、前后内容、发起人、确认人及修改方式。
- AI 修改关联来源对话、输入凭据、AI 执行、提案与具体条目。
- 一次操作修改多个对象时，共享操作标识，可以查看同次操作影响的其他对象。
- 文档和任务详情提供历史时间线与差异查看，来源链接遵守当前访问权限。
- 业务修改、版本与历史记录在同一事务内保存；历史写入失败则整体回滚。
- 恢复历史内容产生新版本，不覆盖原记录；重复确认不重复执行或追加重复历史。
- AI 摘要与用户实际说明分开，不能编造变更原因。

## 4. 第一版功能（当前建议）

第一版围绕工作空间、项目、文档、任务、对话、变更提案与历史记录展开。

- 文档：阅读视图与所见即所得编辑、Markdown 存储、版本历史、恢复及差异查看。
- 任务：标题、描述、验收标准、状态、负责人、优先级、列表与看板、评论与一级回复。
- 对话：在同一项目内讨论，流式显示生成过程，生成待确认的任务提案。
- 提案：展示待创建任务，确认或拒绝整份提案；文档提案尚未实现。

建议暂不做多人实时编辑、自定义工作流、自定义字段、子任务、任务依赖、插件、附件、外部同步、AI 自动写代码、AI 删除正式对象和向量检索。

成员管理已经实现：

- 项目继承工作空间权限，第一版不做私有项目。内容是否可读可写只取决于当前是否为工作空间成员。
- 工作空间只有管理员与成员两种角色。邀请、成员列表和移除已实现：邀请后成为成员，管理员可以移除他人，成员只能退出自己，空间至少保留一名管理员。尚不能把成员提升为管理员。

已实现规则与尚待确认事项：

- 只有提案发起人能够确认或拒绝（已实现）；暂不支持部分应用。
- 第一版使用 Markdown，暂不做多人实时协同编辑。
- 任务与文档用 `DEV-n`、`DOC-n` 引用，编号在工作空间内唯一且不随项目变化。引用只在显示时识别成链接，正文仍存原始文本；对话引用的内容作为不可信资料交给模型，每次最多 6 个，文档正文截断到 12000 字（已实现）。

## 5. 前端界面

### 布局

项目首页是工作台：这条对话占主要宽度，右侧列出本项目的进行中与待办，下方是工作空间概况（项目进度、最近文档、最近动态，由 `GET /api/workspaces/:id/overview` 一次返回）。没有消息时显示大输入框和可直接发送的起点卡片；有消息后记录在上、输入框在下，已确认写入看板的任务显示为产出卡片。没有项目时，第一句话会创建项目并开始这次对话。看板和文档仍是单独页面，可以从右侧打开同一条对话：面板宽度固定且不占满页面，缩小后变成始终悬浮的按钮。生成中的回复按 SSE 快照更新：PHP 持久接收输入后返回 202，agent 把生成作为持久任务执行，刷新或重连恢复最新已提交快照，浏览器断开不会取消生成。模型经 agent 调用 Command Code 的 Chat Completions，默认 `deepseek/deepseek-v4.1-flash`，可由 `CMD_MODEL` 覆盖。文档提案尚未实现，起点卡片只承诺拆出待确认任务。

```text
┌──────────┬──────────────────────────────────────┐
│ 项目导航 │ 问候与概况                             │
│          ├───────────────────────────┬──────────┤
│ 工作台   │ 对话记录 / 起点或这次产出 │ 进行中   │
│ 文档     │                           │          │
│ 看板     │ 输入框                    │ 待办     │
│          ├───────────────────────────┴──────────┤
│          │ 项目进度 · 最近文档 · 最近动态        │
└──────────┴──────────────────────────────────────┘
```

- 项目入口支持从对话开始，也能打开已有内容。
- 查看 AI 产出不离开当前对话；当前项目、文档或任务上下文应可见。
- 区分正在生成、等待确认、已应用、失败和冲突，不能把生成成功显示为修改已生效。
- 变更确认展示摘要、受影响对象和前后差异；冲突时禁止直接覆盖。
- 文档与任务详情具有历史入口，可以追溯来源对话和同次操作。
- 视觉采用 shadcn/ui Nova 中性主题，以内容和差异为主体；组件与交互约束见 `DESIGN.md` 和 `AGENTS.md`。
- 骨架在小屏幕上采用纵向堆叠；业务交互细节和完整视觉稿尚未设计。

| 部分           | 当前状态                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------ |

| 样式           | 已采用 Tailwind CSS v4 与 shadcn 语义主题                                                              |

前端只包含客户端代码，服务端状态由 PHP API 持有；agent 的对话正文不进入浏览器缓存以外的业务表。

| 部分               | 当前推荐或待定状态                                                                |

| 接口形态           | AMPHP 路由（`api/bin/server.php`），JSON 接口与 SSE；内部工具接口只认服务 token   |

TypeScript 使用 6.0 系列，以匹配当前类型检查与静态检查工具的兼容范围。具体版本由包清单和锁文件固定。

## 7. 数据与执行约束（当前设计）

详细表结构与流程见[第一版功能与数据设计](product-and-data-design.md)。

- 核心数据包含用户、工作空间与成员、项目、文档及版本、任务、对话归属与输入凭据、AI 执行、提案及条目、上传与操作记录。
- 对话正文只保存在 agent 的 SQLite；PostgreSQL 保存归属、接收凭据、执行状态和提案。浏览器断线或 agent 重启后按持久状态恢复。
- 当前内容保存在业务表，不采用事件溯源。文档有完整版本快照，任务通过版本号与不可变操作记录提供追踪。
- 使用工作空间隔离数据，禁止跨工作空间或项目关联正式对象。
- 提案是受控的结构化操作，不接受任意表名、字段路径或 SQL。
- 同一提案中新建对象可以使用局部引用，应用时在事务内转换为正式标识。
- 应用前检查目标版本及关键需求依据版本，避免使用已经过期的需求修改内容。
- 模型执行期间不持有数据库事务或行锁。
- 未应用提案和失败执行不能显示成已发生的正式变更。
- 接收凭据、admission、提案内容哈希和终态回写都按稳定标识去重；网络重试与进程崩溃不会重复生成或写入。

## 8. 当前状态与后续

已完成的业务闭环：

> 对话澄清需求 → AI 提交待确认任务提案 → 用户确认 → 事务写入看板与不可变历史。

- 已实现：注册登录、工作空间与成员、项目、文档版本/差异/恢复、任务看板/评论/历史、私有持久对话、任务提案、图片上传与工作空间 S3。
- 已验证：工作空间隔离、权限撤销、版本冲突、重复确认、事务回滚、对话断线与 agent 重启恢复。
- 后续优先级：文档修改提案、成员角色提升、邮箱验证与密码找回、浏览器端 E2E、数据库备份与恢复演练。
