# 第 3 阶段 code review

范围：兼容数据库迁移、PHP 提案和内部工具接口、agent 业务工具、nginx 内网隔离，以及真实 HTTP / 进程恢复测试。没有切换浏览器路由或操作实际业务数据。

## 发现与修复

- P1：内网鉴权原先按原始 URL 判断路径，但 AMPHP Router 会先 `rawurldecode()` 再分发。编码前缀 `/%69nternal/` 和编码分隔符 `/internal%2f` 因此可以命中内部 handler 而漏过 token 校验。加入回归测试，修复前复现 200；鉴权按同样的单次解码判断，失败直接返回 401。完整测试验证普通、编码前缀及编码分隔符均无法使用浏览器 cookie 冒充服务身份。
- P2：提案工具转发 PHP 的完整响应，会把最多八条长任务再次塞入模型上下文，还可能触发输出截断。改为验证并只返回提案 UUID 与状态回执；完整条目仍由 PHP 保存并供用户读取。项目摘要工具也设置了足够容纳四十条任务和四十条文档摘要的输出上限。
- P2：原有权限测试没有实际保存待保护消息，跨空间引用测试也仅覆盖不存在的编号。补充真实私有消息，以及另一工作空间中确实存在的文档，验证提案不会带出对话、编号不会越界读取。

## 已复查的业务约束

- 内网接口只认服务 token，nginx 拒绝 `/internal/`；公开提案接口仍要求登录，不因携带服务 token 而取得用户身份。
- 工具的 runId 从持久输入记录读取并以任务 memo 保存，不接受模型参数指定身份、执行或 URL。恢复时重放相同执行；HTTP 超时、取消、响应大小及重试均有界，禁止重定向和转发内部错误正文。
- PHP 根据持久执行查找发起人，并重新检查其当前成员关系与私有归属。旧 legacy 执行不允许调用新工具。成员分享锁先于提案、项目与任务写锁，成员移除不能留下新的待确认提案。
- 提案按执行唯一，规范化摘要与条目后记录内容哈希；响应丢失后的相同内容重试返回同一提案，包括执行已进入终态的情况。不同内容返回 409。
- 只有发起人能确认或拒绝。确认复用任务创建和不可变历史写入，在一个事务内分配工作空间编号、创建任务、关联提案条目和更新状态；重复确认不重复创建，失败整批回滚。
- 迁移是新增结构，保留 `conversations.project_id` 唯一约束和旧触发消息写法，不提前实施私有数据切换。新执行通过外键绑定输入凭据、发起人和执行 ID，触发消息与新输入恰好选一个。

## 验证与结论

PHP 测试启动真实 AMPHP 进程及临时 PostgreSQL schema，覆盖并发提交和确认、第二条任务的历史写入失败、权限撤销竞态、私有消息隔离、跨空间引用、长度限制和 legacy 执行兼容。agent 使用真实进程、临时 SQLite 和本地模型 / 业务 API 替身，覆盖提案外部保存后 SIGKILL、重启工具重放、身份注入拒绝和内部错误清理。

修复后 PHP 45 项测试与 agent 9 项测试通过，compose 配置校验通过。按上述范围复查无遗留阻断项，可进入第 4 阶段。PHP 对话入口、输入接收协调、SSE 转发及持久终态对账仍待实现；浏览器继续使用 legacy。
