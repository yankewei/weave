# 第 2 阶段 code review

范围：agent 的 HTTP、Pi Durable/SQLite 状态、Command Code 接入、历史导入、SSE 和进程级集成测试。复查遵守只使用 Pi Durable 公共接口的要求，未切换 nginx，也未运行真实数据迁移。

## 发现与修复

- P1：输入准备完成、尚未调用 `submit()` 时进程退出，不能仅靠 Harness 的模型任务恢复。启动时根据持久输入凭据补交同一 requestId，并先检查 admission 是否已封存。新增直接构造该持久状态的进程恢复测试，同时验证封存记录不会重新生成。
- P1：先前用普通异步迭代读取请求，超过正文限制时抛错会销毁输入流，客户端可能得到连接错误而非 HTTP 413。改用不在提前退出时销毁流的迭代方式，再由请求处理器排空正文；通过真实 HTTP 测试验证 4 MiB 限制和服务继续可用。
- P1：导入标记曾被当作不可变归属的一部分，封存后正常模式再次创建映射会冲突。归属 UUID 仍不可更改；只有已封存导入允许正常模式幂等取得原映射。新增切换后的回归断言。
- P2：历史 authorType 校验曾经先转字符串，数组 `["user"]` 可通过检查。改为严格枚举比较，并补充作者名长度校验和嵌套错误类型的回归断言。
- P2：准备输入与实际提交之间可能改变模型配置。首次提交前选择当前主机配置的模型；已提交 requestId 先查重，不能因配置改变再次生成。
- P2：读取快照不能用无效空对象初始化输入文档。缺失持久输入记录视为状态损坏并返回服务错误，不创建不完整记录。
- P2：Pi Session 因存储错误关闭后，HTTP 健康检查不能继续报正常。监听持久会话失败并关闭连接、退出为非零状态，由部署的重启策略恢复。

## 验证与边界

集成测试启动实际 `src/server.ts` 子进程、临时 SQLite 和本地 OpenAI-compatible SSE 模型替身，覆盖并发查重、模型缺失、生成中 SIGKILL、提交前恢复、admission 封存、SSE 断连和重连、供应商错误清理、历史批次回滚、顺序/摘要封存及跨重启分页。不使用真实模型密钥或工作空间数据。

已按上述故障路径复查，无遗留阻断项。第 2 阶段只提供内网持久对话，模型当前仅讨论和澄清需求；业务工具、提案保存与持久终态同步属于第 3/4 阶段。nginx 继续把浏览器对话和提案交给 legacy，不能提前切流。

运行约束：同一 SQLite 文件仍只允许一个进程拥有；import 模式既不接受输入也不启动模型调度。修改模型配置应在运行完成后进行，已准备的供应商请求仍按 Pi Durable 固定的请求配置恢复。
