# 第 5 阶段：直接切换持久对话

用户已明确没有需要保留的旧对话，不执行历史导入，不建设旧数据兼容流程。过去阶段的 review 记录保留为当时的检查记录，当前方案以本文为准。

## 实施顺序

1. 删除 agent 的历史导入接口、import 模式、导入状态文档和相关测试；不再复制 PostgreSQL 消息到 SQLite。
2. 新增迁移，将 `conversations` 的唯一约束改为 `(project_id, created_by)`，删除 `import_status`。不修改已提交迁移，不清空开发或生产数据库。任务、文档、提案以及持久输入的约束保留。
3. 更新 web 契约：发送接收凭据、run/syncStatus、SSE 快照、历史分页、提案处理独立响应。
4. 发送前生成稳定 requestId，将未确认接收的消息按项目保存到当前登录会话的 sessionStorage；接收结果未知时可用同一标识重试。已知接收后不重新发送，改为读取和订阅；明确拒绝的请求解除重试状态并保留草稿。
5. 把 POST 接收与 GET SSE 分开。组件卸载只取消读取/订阅；刷新读取执行状态，断线按上限 15 秒退避重连，401/403/404 停止；生成终态但 syncStatus 仍 pending 时轮询到完成。
6. 保留已加载的更早消息，按 UUID 合并快照，不能把完整快照误作 token 增量。提供更早消息加载和失败重试；不添加自制滚动逻辑。
7. 确认/拒绝只更新提案，随后刷新对话及项目任务概况；待确认提案和未同步执行不得被新消息绕过。
8. nginx 移除对话与提案的 legacy 覆盖，显式关闭 SSE 缓冲；就绪检查同时迁到 PHP，默认 compose 不再启动 legacy；迁移/测试源码的清理在第 6 阶段完成。
9. 使用隔离 PostgreSQL schema、临时 SQLite 和受控模型验证真实 PHP/agent 链路；验证前端发送重试、重连、刷新恢复、项目隔离、分页和提案确认。补充浏览器检查。
10. 做 code review，修复发现的问题并增加必要回归验证，运行根目录 `pnpm check`，更新 README、当前契约和阶段记录。

## 验收

- 同项目不同成员有各自私有对话，其他成员和管理员不能读取对话正文。
- 重试不重复生成；刷新不重复发送已接收的输入；项目切换不带入上一项目的回复或错误。
- 断线不终止生成，重连展示最新快照；终态对账后能看到提案和任务应用结果。
- 分页加载不会被快照覆盖、重复或跳过；确认/拒绝仍使用官方控件与既有确认流程。
- 运行路径不再依赖导入标志或导入模式，浏览器对话与提案请求只到 PHP。
- 没有执行旧消息数据复制、清空实际数据库或线上切流操作；本轮交付代码、隔离验证和部署说明。
