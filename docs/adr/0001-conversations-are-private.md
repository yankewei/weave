# 对话归发起人私有

一个项目可以有多条对话，每条对话只属于发起它的成员，其他成员（包括管理员）都看不到，访问时按不存在处理。这样可以放心地和 AI 来回试探想法，不必担心半成品被团队看到。代价是可追溯性只公开到提案：其他人能看到一条 AI 任务的发起人、确认人、提案摘要和条目，看不到产生它的讨论。提案摘要本来就是写给确认人看的说明，足以解释任务的来由。

一旦对用户承诺了私有，以后改回共享就等于泄露已有内容，所以这个决定很难回退。

## Considered Options

- 全员共享（原设计：每个项目一条共享对话）：追溯链完整，但试探性的讨论也全部公开。
- 向其他人公开触发消息：单独一句话脱离上下文，容易被误读。
- 确认提案时把对话分享出来：等于部分放弃私有，权限模型也会变复杂。

## Consequences

- 迁移时，原有共享对话整条归 `created_by`，其他成员在其中发起、尚未处理的提案一律拒绝。
- 成员被移除后，他的对话保留但无人可见；重新加入后恢复可见。
